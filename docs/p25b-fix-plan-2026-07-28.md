# P2.5-b 差し戻し修正計画

> 作成: 2026-07-28 / 根拠: `docs/review-p25-code-2026-07-28.md`（**Request Changes** / Must Fix 2件）, `docs/security-audit.md`「P2.5 ハードニング監査」（Critical 0 / High 0 だが **P3 着手条件1 が未達**）

## 差し戻し理由
両レビュワーが**独立に同一の結論**に到達した:

> SEC-021（未認証の第三者が管理者ログインを恒久封鎖できる）の**脅威クラスが閉じていない**。
> 攻撃ベクタが「アカウント軸」から「グローバル軸」へ移動しただけで、攻撃コストがむしろ下がった
> （5req/15分 + 管理者メール既知 → **100req/分 + 知識不要**）。

Security Agent は実装モジュールに攻撃シナリオを直接投入して**実測で再現**している:
- 単一 IP から 120 リクエスト → グローバル軸 100/100 到達 → **別 IP の正規管理者が正しいパスワードで `outcome=rate-limited verified=false`**

さらに「締め出しは起こらない」という**事実に反する記述**がコードコメント・`docs/tech-stack.md`・テスト契約書の3箇所に残存している。

### 教訓（記録）
P2 では「**テストが green でも本番経路が守られていない**」型の不具合が起きた。
P2.5 では「**red だったテストが全部 green になっても、脅威が閉じていない**」が起きた。
テストは契約を満たし、実装は契約に忠実だった。**問題は契約のほうにあった**。
→ 以後、セキュリティ是正では「テストが green か」ではなく「**脅威シナリオが実測で再現しなくなったか**」を完了条件にする。

## 進め方
1. **Test Agent**: #1〜#4 の失敗テスト（red）を追加。#1 は「他者がグローバル上限を使い切っても正しい資格情報は通る」不変条件を必ず含める。
2. **Impl Agent**: red → green。既存 163 unit / 28 integration / 82 e2e を退行させない。
3. **再レビュー**: Senior 再検収 + Security 再監査。**Security は攻撃シナリオの実測再現による検証を必須とする**（テスト green だけを根拠にしない）。
4. 条件1（#1・#2）クリアで **P3 着手可**。
