# UI設計: コース・料金 横断比較（F-002）

> 準拠: `/DESIGN.md`、共通コンポーネントは `./layout.md` §7 を参照。
> 対応要件: `functional-spec.md` F-002（画面仕様・API仕様・データモデル）
> スコープ: `category='LICENSE'` のコースのみ。ドローン/建機/追加講習は `course-detail.md`（F-022部分）を参照。

## ビジュアルコンセプト

- 「校舎×免許種別×受講形態」を**3段階の絞り込み**で迷わせずに提示する。フィルタは常にURLクエリと同期し、共有・ブラウザ戻るで状態が保持される。
- モバイルは絞り込みチップ→カード一覧、デスクトップは絞り込みチップ+比較テーブルの両方を提供し、じっくり比較したいユーザー（保護者層等）にはテーブルビューで一覧性を確保する。

## フィルタ仕様（F-002画面仕様に対応）

### 校舎フィルタ
- `FilterChipGroup`（単一選択）: `すべて` / `岩滝` / `網野`。初期値 `すべて`。

### 受講形態フィルタ
- `FilterChipGroup`（単一選択、トグル）: `通学` / `合宿`。初期値 `通学`（F-002画面仕様表準拠）。

### 免許種別フィルタ（2階層）
- 第1階層 `FilterChipGroup`: `すべて` / `普通車` / `プロ免許`。
- `普通車` 選択時のみ第2階層を表示: `AT` / `MT` / `指定なし`（`transmission` 属性フィルタ、初期値=指定なし）。
- `プロ免許` 選択時のみ第2階層を表示: `準中型` `中型` `大型` `普通二種` `大型二種` `けん引` `大型特殊` `普通自動二輪` のチップ（複数選択可、`FilterChipGroup multiple`）。「プロ免許」はUI上のグルーピング値であり、APIには実際に選択された `licenseType` 配列（複数可）を渡す。何も選択せず「プロ免許」だけ選んだ場合は非ORDINARYの全種別を対象とする。
- ヘッダーナビ「プロ免許」からの遷移時はこの状態（第1階層=プロ免許、第2階層=すべて未選択=非ORDINARY全件）を初期状態として展開する。

```ts
FilterChipGroup:
  props: {
    label: string                 // アクセシブルネーム用（視覚的にはSRのみの場合あり）
    options: { value: string; label: string }[]
    selected: string | string[]
    multiple?: boolean
    onChange: (value: string | string[]) => void
  }
```
- 実体は `role="group"` + 各チップ `role="radio"`（単一選択）または `aria-pressed`（複数選択トグル）。タッチターゲット44px、横並びで折り返し可、モバイルは横スクロール可（`overflow-x: auto`）。

### URL同期
- フィルタ状態は `?school=&format=&license=` （複数値はカンマ区切り）としてURLに反映し、`GET /api/courses` に渡すクエリと1:1対応させる（F-002 API仕様）。
- ブラウザバック/共有URLで同じ絞り込み結果を再現できること（受け入れ確認項目としてTest Agentに引き継ぐ）。

## 結果表示: CourseCard一覧（Mobile / Tablet）

- `CourseCard`（`layout.md` §7.2）をGrid表示: Mobile 1列 / Tablet 2列。
- 各カードのバッジ順序は `layout.md` §7.1 の並び順ルール（校舎→受講形態→給付金/助成金）に従う。
- ソート順: `sortOrder` 昇順固定（ユーザーによる並べ替えUIは本バッチでは対象外）。

## 結果表示: CourseTable（Desktop ≥1024px）

DESIGN.md Layout Principles「デスクトップは全項目を1画面のテーブルで表示」に対応する専用コンポーネント。

```
| 校舎 | 免許種別 | 受講形態 | 最短日数 | 料金〜 | 給付金/助成金 |      |
|------|---------|---------|---------|-------|-------------|------|
| ●岩滝 ●網野 | 普通車(AT) | [通学] | 15日 | ¥225,500 | [給付金対象] | [詳細][申込] |
```

```ts
CourseTable:
  props: { courses: CourseCardProps[] }  // CourseCardと同一データ形状を再利用
```

- 行ホバーで背景 `Background(#F8FAFC)`。
- 料金列は `font-variant-numeric: tabular-nums`、右揃え。
- 校舎列は `Badge(variant="school")` を最大2つ並べる（アウトライン形状のまま、テーブルセル内でも縮小しない）。
- 「詳細」「申込」列は `CTAButton size="compact"` を2つ並べる（テーブル行の高さに収めるため）。
- テーブル自体は `overflow-x: auto` のラッパーで囲み、1280px未満でも列が潰れる場合は横スクロールにフォールバックする（真の「潰れ」対策）。

## 空状態・エラー状態

| ケース | 対応 |
|--------|------|
| E-002-1 条件一致0件 | `EmptyState` message="条件に合うコースがありません" actionLabel="フィルタをリセット"（全フィルタを初期値に戻す） |
| E-002-2 データ取得失敗 | `ErrorState` message="情報を取得できませんでした" onRetry=再フェッチ |

## コース詳細・申込への導線

- `CourseCard`/`CourseTable`の「詳細」→ `/courses/[id]`（`course-detail.md`）。
- 「このコースで申込む」→ `/apply?courseId=[id]&type=APPLICATION`（F-002画面仕様「選択コースをフォームに引き継ぐ」に対応。フォーム側F-008でcourseIdを事前選択状態にする）。

## インタラクション定義

| トリガー | アニメーション | 持続時間 | イージング |
|---------|-------------|---------|----------|
| フィルタチップ選択 | 背景色トランジション | 150ms | ease-out |
| フィルタ変更→結果更新 | 結果リストのフェード切替（ローディング中は既存結果を薄く表示） | 200ms | ease-out |
| CourseCard/Tableホバー | Shadow上昇 / 行背景変化 | 150-200ms | ease-out |

## データソース

`GET /api/courses?school=&license=&format=`（F-002 API仕様、Response型は `functional-spec.md` 参照）。フィルタ変更のたびに Route Handler へフェッチ（クライアント側 `"use client"` のフィルタコンポーネント + サーバーへの再フェッチ、もしくは Server Component + `searchParams` によるフルSSRのいずれかで実装可。SEO上は初回アクセス時にサーバーで絞り込み済みHTMLを返す方式を推奨）。

## アクセシビリティ

- フィルタ変更後の結果件数は `aria-live="polite"` の隠しテキストで通知（「6件のコースが見つかりました」）。
- `CourseTable` は `<table>` + `<th scope="col">` を用いた正規のテーブルマークアップとし、スクリーンリーダーで行/列の対応が読み上げられるようにする。
- チップのキーボード操作: 矢印キーで同一グループ内を移動、Space/Enterで選択（ネイティブradio/buttonのセマンティクスを使えば追加実装不要）。
