### 修正の作法（両レビュワーが明示した要求）

**SEC-043 は「コードを直す」だけでは不十分。**
> 「警告をコメントに書く」ことは、呼び出し側が読まなければ機能しない。**型で強制する**（`ClientIpResolution` を分解せずに渡す API にする、`trusted` を必須引数にする）か、**テストで固定する**以外に、この型の再発を止める手段は無い。 — Security 監査

`lib/http-guard.ts:86-94` は「`trusted` を捨てる呼び出しはこの防御を無効化する」と**名指しで警告していた**にもかかわらず、新しいラッパが `clientIp(request).key` だけを取り出した。**同じ警告を書き足すのは対策にならない。**

**SEC-042 は「新しい型の失敗」。**
> `form-session.test.ts:129` は「壊れた形式でも例外を投げず null」という**正しい契約**を書いているのに、与えた 5 つの入力がすべて ASCII だったために `Buffer` 長の不一致に到達しなかった。
> **契約が正しくても、その契約を検証する入力の選び方が脅威モデルと一致していなければ意味がない。**

→ テスト追加時は**入力の選び方が脅威モデルを覆うか**を明示的に点検すること（マルチバイト・不正 UTF-8・長さ境界）。
