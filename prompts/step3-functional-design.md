以下のプロンプトを新しいClaude Codeインスタンスにコピー&ペーストしてください。
プロジェクトディレクトリで実行すること。

---

```
まず CLAUDE.md を読んでプロジェクトの開発方針とエージェント構成を理解してください。

次に以下のドキュメントを全て読んでください:
- /docs/product-concept.md（プロダクトコンセプト）
- /docs/pr-faq.md（PR FAQ）
- /docs/business-spec.md（業務仕様書 ← Step 1-2で作成済み）

これからStep 3「機能設計」を進めます。CLAUDE.md に定義されたマルチエージェントTDDフローに従って作業してください。

## やること

業務仕様書のMVPスコープに含まれるユーザーストーリーを、テスト可能な機能要件に詳細化します。

### Phase A: 機能要件の対話的詳細化

business-spec.md のMVPユーザーストーリーを1つずつ取り上げ、私と対話しながら以下を決めてください:

1. **画面仕様**: 各画面の構成要素（入力フィールド、ボタン、表示項目）
2. **振る舞い仕様**: 正常系・異常系・境界値の具体的な動作
3. **API仕様**: エンドポイント、リクエスト/レスポンス、エラーレスポンス
4. **データモデル**: エンティティ定義、リレーション
5. **バリデーションルール**: 各入力項目の制約

各機能にはF-IDを付与してください（F-001, F-002, ...）。
曖昧な点や判断が必要な点は必ず私に質問してから決定してください。
一度に全部聞かず、1機能ずつ順番に進めてください。

### Phase B: Spec Agentで仕様書に書き出し

対話で合意した内容を、Taskツールで Spec Agent を起動して /docs/functional-spec.md に書き出してください。
起動時は .claude/skills/spec.md を読ませてください。

### Phase C: 設計レビュー + UI設計（並列）

functional-spec.md が完成したら、Taskツールで以下を並列起動してください:

1. Senior Engineer Agent（.claude/skills/senior-review.md）
   → 設計レビューを実施、結果を /docs/review-design-[日付].md に出力
2. Designer Agent（.claude/skills/designer.md）
   → UIデザイン仕様を /docs/ui-design/ に出力

Senior Engineerが Request Changes を出した場合は、指摘内容を私に共有し、修正方針を相談してください。

### Phase D: 次ステップへの橋渡し

全機能のレビューが Approve になったら、以下をサマリーとして報告してください:
- 確定した機能一覧（F-ID、機能名、優先度）
- UIデザイン仕様の概要
- Senior Engineerの主な指摘と対応結果
- 次のステップ（テスト設計）に必要な情報が揃っているかの確認

## 進め方の注意

- 私の承認なく仕様を確定しないでください
- 技術選定で迷う場合は選択肢とトレードオフを提示してください
- 1機能の詳細化が終わるごとに「次の機能に進みますか？」と確認してください
- デザインに関してはゲーム的なUI要素を積極的に提案してください
```
