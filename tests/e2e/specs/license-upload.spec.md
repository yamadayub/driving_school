# E2E シナリオ: F-009 免許証写真アップロード

## シナリオ名: 免許証写真の添付と申込送信

### 前提条件
- dev DB が稼働し `pnpm db:seed` 済み
- E2E サーバーが **`TRUST_PROXY=1` で起動**している（RV-P3B-019 / 「軸を分ける」）
- ブラウザは **chromium / firefox**（**WebKit は対象外**。理由は下記）
- ストレージは**ローカルアダプタ**（外部アカウント不要）

### テストステップ

> ⚠️ **フォームはステップ式である**（`components/apply/form-model.ts:38`）。
> `APPLICATION` は `course → personal → license → preference → review` の 5 ステップ、
> `INQUIRY` は `personal → review` の 2 ステップ。**1 画面ではない。**

1. `/apply` を開き、種別「入所申込」を選ぶ（`apply-type-application`）
2. **コースステップ**: 「コース」を選択して「次へ」（`apply-next`）
3. **個人情報ステップ**: 氏名 / 氏名カナ / 生年月日 / メールアドレス / 電話番号 を入力して「次へ」
4. **免許ステップ**: 免許証の表画像に **正しい JPEG** を選択する（`license-photo-front`）
5. プレビュー（`license-photo-front-preview`）が表示されることを確認する
6. 確認ステップ（`apply-step-confirm`）まで進み、同意（`input[name="privacyConsent"]`）にチェック
7. 送信間隔下限（3 秒）を跨いでから送信（`apply-submit`）
8. 完了画面の受付番号（`complete-receipt`）に到達する

> ⚠️ **ラベルは実装のとおりに書くこと。** 初版は `お名前` / `フリガナ` という
> **実在しないラベル**を使い、14 件失敗 / 44.7 分を消費した。
> 正しくは `氏名` / `氏名カナ` / `生年月日` / `メールアドレス` / `電話番号` / `ご質問・ご要望`。
> 実在性は `tests/unit/e2e-selector-contract.test.ts` が固定している。

### 期待結果
- プレビューが表示される
- 送信が成功し、受付番号が表示される
- `sessionStorage` の下書きに `objectKey` / `uploadToken` / `previewUrl` / `licensePhotos` が**含まれない**
- 完了画面到達後、下書きが**削除されている**

### テストステップ

2. **実体が HTML** のファイルを `license.jpg` / `image/jpeg` として選択する

## ⚠️ WebKit を対象外にした理由（**黙って除外しない**）

**WebKit は `http://localhost` で `__Host-` 接頭辞（`Secure` 必須）の Cookie を受理しない。**
そのため WebKit の E2E は**常に「Cookie 無し」経路**を走っており、
フォームセッション Cookie 軸（uploads の Tier B / Tier D 判定の土台）を**一度も通っていない**。

uploads は Cookie 軸に依存するので、WebKit で走らせても
**検証したい防御を 1 つも検証しないまま green になる**。
「3 ブラウザで green」と記録して実際には 2 ブラウザでしか測っていない状態を作らないため、
`test.skip(browserName === 'webkit', ...)` に理由を書いて明示的に除外する。

**中期課題**: E2E を HTTPS で回せば WebKit でも Cookie 経路を通せる。
本単位ではスコープ外（設計文書 `docs/test-design-p3c2-2026-07-29.md` §9）。

## ⚠️ RV-P3B-019 —「上限を緩める」のではなく「軸を分ける」

現構成（縮退）では全利用者が共有 `unknown` バケットを使うため、
E2E の通常操作だけで無コスト枠（10 枚/10 分）を超え、**送信成功の E2E が原理的に書けなかった**。

**採った形**: E2E サーバーを `TRUST_PROXY=1` で起動し、**テストごとに異なる `X-Real-IP` を送る**。

- **上限を 1 つも緩めていない**（閾値も窓も本番と同じ）。
- 変えたのは「発信元軸が要求元ごとに分かれる」ことだけで、
  それは**本番（Vercel）で実際に成立している状態**そのものである。
  縮退構成のほうが本番と乖離していた。
- `x-real-ip` を使うのは、env 由来の信頼では **`x-real-ip` が `x-forwarded-for` より優先される**
  という P3-c1（NEW-005）の契約に合わせるため。

> **`TRUST_PROXY=1` は E2E の webServer 環境にのみ設定すること。**
> 本番の設定に混ぜてはならない（前段が XFF を上書きしない構成ではクライアントが IP を名乗れる）。
