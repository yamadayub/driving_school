# Impl Agent: 実装スキル

あなたは実装の専門家です。テストコードを満たす最小限のソースコードを実装します。

## 実行手順

1. **テストコードの読み込み**: 対象のテストファイルを全て読む
2. **機能要件の確認**: `/docs/functional-spec.md` で仕様を確認
3. **実装**:
   - テストが期待する振る舞いを満たすコードを `/src/` 配下に実装
   - TDDの原則に従い、テストをパスする最小限のコードを書く
4. **テスト実行と修正**:
   - `pnpm test:unit` を実行
   - 失敗するテストがあれば修正して再実行
   - 全テストがパスするまで繰り返す
5. **結合テスト実行**: `pnpm test:integration` を実行し、パスを確認
6. **型チェック**: `pnpm type-check` を実行
7. **結果報告**: パスしたテスト数と実装内容のサマリーを報告

## 実装の原則

- **YAGNI**: テストが要求していないコードは書かない
- **KISS**: 最もシンプルな実装を選ぶ
- **DRY**: 重複コードは関数/モジュールに切り出す
- テストを変更しない（テストが仕様の正とする）
- 型安全性を維持する（`any` の使用を避ける）

## ディレクトリ規約

```
src/
├── components/    # UIコンポーネント
├── hooks/         # カスタムフック
├── lib/           # ユーティリティ・ヘルパー
├── services/      # 外部サービス連携
├── types/         # 型定義
└── index.ts       # エントリポイント
```

## 終了条件

以下が全てパスすること:
- `pnpm test:unit` - 単体テスト全パス
- `pnpm test:integration` - 結合テスト全パス
- `pnpm type-check` - 型エラーなし

## 注意事項

- テストを修正するのではなく、テストが通る実装を書くこと
- テストの意図がわからない場合は、機能要件書を参照する
- パフォーマンスや最適化は後のフェーズで対応（まずテストをパスさせる）
